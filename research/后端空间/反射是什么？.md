# 反射是什么？

要真正掌握反射（Reflection），最直观的方式就是看代码。

一句话概括反射的本质：**在程序运行期间，你可以“反向”探测和操作一个类的内部结构（属性、方法、构造函数），即使你在写代码的时候并不知道这个类具体是什么。**

为了让你看清楚这套“黑科技”是怎么运作的，我们来手写一个最简单的例子，模拟刚才提到的“IoC 容器”是如何利用反射来干活的。

### 1. 准备工作：一个普通的 Java 类

假设我们有一个非常普通的 `User` 类。请特别注意，它的属性是**私有**的，且有一个**私有**方法。在正常的代码逻辑中，外部是绝对无法直接访问这些私有成员的。

Java

```
package com.example; // 假设包名

public class User {
    // 私有属性
    private String name = "默认少侠";
    public int age = 18;

    // 无参构造方法
    public User() {
        System.out.println("User 无参构造被调用了！");
    }

    // 私有方法
    private void secretMethod(String message) {
        System.out.println(this.name + " 的秘密是：" + message);
    }
}
```

### 2. 反射实战演示

现在，我们写一个测试类。我们要达到三个目的：

1. 动态创建一个 `User` 对象（但不使用 `new` 关键字）。
    
2. 强行修改那个私有的 `name` 属性。
    
3. 强行调用那个私有的 `secretMethod` 方法。
    

Java

```
import java.lang.reflect.Field;
import java.lang.reflect.Method;

public class ReflectionDemo {
    public static void main(String[] args) {
        try {
            // ----------------------------------------------------
            // 步骤一：获取“类”的图纸（Class 对象）
            // 在反射中，一切操作的起点都是获取这个类的 Class 对象。
            // 假设这是通过配置文件读取到的字符串类名
            // ----------------------------------------------------
            String className = "com.example.User"; 
            Class<?> clazz = Class.forName(className); 
            System.out.println("成功加载类模板：" + clazz.getName());

            // ----------------------------------------------------
            // 步骤二：利用反射实例化对象 (模拟 IoC 容器创建 Bean)
            // 不再使用 new User()，而是通过类模板来创建
            // ----------------------------------------------------
            Object userInstance = clazz.getDeclaredConstructor().newInstance();
            // 此时控制台会打印出："User 无参构造被调用了！"

            // ----------------------------------------------------
            // 步骤三：利用反射强行操作私有属性 (模拟依赖注入)
            // ----------------------------------------------------
            // 1. 拿到名为 "name" 的属性定义
            Field nameField = clazz.getDeclaredField("name");
            
            // 2. 暴力破解！打破 private 的访问限制
            nameField.setAccessible(true); 
            
            // 3. 将我们刚刚创建的 userInstance 对象中的 name 属性，改成 "王雷"
            nameField.set(userInstance, "王雷"); 
            System.out.println("私有属性修改成功！");

            // ----------------------------------------------------
            // 步骤四：利用反射强行调用私有方法
            // ----------------------------------------------------
            // 1. 拿到名为 "secretMethod" 的方法定义，并指明它需要一个 String 类型的参数
            Method secretMethod = clazz.getDeclaredMethod("secretMethod", String.class);
            
            // 2. 暴力破解！打破 private 的访问限制
            secretMethod.setAccessible(true);
            
            // 3. 让 userInstance 这个对象，去执行这个私有方法，并传入参数
            // 这相当于在传统代码里写：userInstance.secretMethod("今天练习了吉他")
            secretMethod.invoke(userInstance, "今天在编写 ToolKit 桌面应用！");

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

### 3. 代码运行结果分析

如果执行上述 `ReflectionDemo`，控制台的输出将是：

Plaintext

```
成功加载类模板：com.example.User
User 无参构造被调用了！
私有属性修改成功！
王雷 的秘密是：今天在编写 ToolKit 桌面应用！
```

**看懂了吗？** 我们在没有直接使用 `new User()`，并且面对的是 `private` 限制的情况下，依然像开了上帝视角一样，随心所欲地创建了对象、修改了私有数据、调用了私有方法。

这就是 IoC 容器在幕后所做的事情。当它看到你的 `@Autowired` 或配置要求时，它就在底层用这种 `Field.set()` 的方式，把你需要的对象硬塞进了你的私有属性里。

### 4. 拓展：反射为什么是框架的灵魂？

在业务开发中（比如编写前端控制器、处理数据库逻辑），我们很少直接写反射代码，因为代码可读性差且有性能损耗。但在**写框架**或者**写工具类**时，反射是不可替代的。

想象一下你正在用 Java Swing 编写你的桌面应用 **ToolKit**：

如果你想做一个“通用配置映射工具”，将外部的 properties 配置文件自动赋值给你程序里的某个对象的属性。如果没有反射，你只能老老实实写：

`if(key.equals("color")) { obj.setColor(value); }`，每多一个属性就要多写一个 if。

有了反射，你只需要写一段通用代码，拿到配置文件里的 key（比如 `color`），利用反射拼接出 `setColor` 方法并调用它，无论传入什么类，这段逻辑都能通用。
