# int 和 Integer有什么区别？

关于 `int` 和 `Integer` 的区别，以及“对象类型”的概念，这是现代面向对象编程（以 Java 为典型代表）中非常核心的内存与类型系统基础。下面为您进行详尽的专业解析。

  

## `int` 与 `Integer` 的核心区别

`int` 是**基本数据类型（Primitive Type）**，而 `Integer` 是 `int` 的**包装类（Wrapper Class）**，其本质上是一个对象。

  

这两者在底层机制和使用场景上有明确的界限：

  

|**特性**|**int (基本数据类型)**|**Integer (对象/包装类)**|
|---|---|---|
|**数据本质**|纯粹的二进制数值。|封装了基本类型数值的完整对象。|
|**内存位置**|局部变量直接存储在**栈内存 (Stack)** 中。|对象实例存储在**堆内存 (Heap)**，变量只在栈中保留一个引用（地址）。|
|**默认值**|`0`|`null`（非常适合在数据库操作中表示“未赋值”或“缺失”状态）。|
|**泛型支持**|不支持。例如 `List<int>` 会导致编译错误。|支持。例如 `List<Integer>` 是标准的集合用法。|
|**内存开销**|极小，固定占用 4 个字节。|较大，除了实际数据外，还包含对象头、对齐填充等（通常在 16 字节以上）。|

## 什么是对象类型（引用类型）？

对象类型（Object Type），在很多编程语言中也常被称为**引用类型（Reference Type）**。包括您自己编写的类（Class）、数组（Array）、接口（Interface）以及字符串（String），都属于对象类型。

  

当您声明一个对象类型的变量时，**该变量并不直接保存对象的数据本身**。相反，它保存的是一串“内存地址”（即引用），这串地址指向内存堆（Heap）中实际存放数据的空间。

### 对象类型的核心特征：

1. **动态分配：** 对象类型通常是通过 `new` 关键字在程序运行时动态分配内存空间创建的。
    
      
    
2. **不仅有状态，还有行为：** 基本类型仅仅是一个干瘪的数值，而对象类型可以携带复杂的属性，并提供操作这些属性的方法（例如 `Integer.parseInt()`）。
    
      
    
3. **生命周期由垃圾回收器管理：** 栈内存中的基本类型变量会随着方法执行结束而立刻自动销毁；而堆内存中的对象在失去所有引用（没有任何变量指向它）后，需要等待垃圾回收器（Garbage Collector, GC）在后台统一进行清理。
    
      
    

## 拓展深度：自动装箱与 IntegerCache 陷阱

在实际开发中，编译器允许我们在 `int` 和 `Integer` 之间直接赋值，这被称为**自动装箱（Autoboxing）**和**自动拆箱（Unboxing）**。例如，写下 `Integer a = 10;` 时，底层其实自动执行了 `Integer.valueOf(10)`。

  

但这其中隐藏着一个极其重要的高频陷阱：**`Integer` 缓存机制 (IntegerCache)**。出于性能优化考虑，Java 底层默认预先创建并缓存了 `-128 到 127` 之间的所有 `Integer` 对象。

  

Java

```
Integer x = 100;
Integer y = 100;
System.out.println(x == y); // 结果为 true。因为 100 在缓存范围内，x和y指向了内存中同一个对象。

Integer a = 200;
Integer b = 200;
System.out.println(a == b); // 结果为 false。超出缓存范围，每次都在堆内存中创建了全新的对象，地址不同。
```

> **专业建议：** 正因为变量存储的是内存地址，所以在比较两个对象类型（包括 `Integer`）的值是否相等时，**永远推荐使用 `.equals()` 方法**。直接使用 `==` 比较的是它们的内存地址，极易引发难以察觉的 Bug。
