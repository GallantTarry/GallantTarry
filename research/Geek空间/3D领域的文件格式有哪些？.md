# 3D领域的文件格式有哪些？

`.gltf`（GL Transmission Format）被业界公认为“3D 领域的 JPEG”。它是由 Khronos Group（制定 OpenGL 和 WebGL 标准的组织）专门为现代网络和实时渲染设计的开源 3D 格式。

  

传统 3D 模型文件往往极其庞大且解析缓慢，而 `.gltf` 的核心优势在于**传输极快、前端解析开销极低**。它的文件结构是基于 JSON 的，用纯文本记录了场景的层级、材质、动画和灯光信息，同时将笨重的顶点数据和贴图分离保存在外部的 `.bin` 和图片文件里。

  

我们在官方仓库里经常同时看到 `.gltf` 和 `.glb`，其实它们是同一个东西的两面：**`.glb` 就是把 `.gltf` 的 JSON 结构、`.bin` 数据和所有图片贴图打包压缩成的一个单文件**。对于前端接入来说，单文件的 `.glb` 是最优解，因为它只需要一次网络请求。

  

### 3D 领域常用的格式梯队

3D 圈子的格式多达几十种，但由于应用场景的严格区分，主流且常用的核心格式其实就以下五类：

  

**1. Web 端与实时渲染霸主：`.gltf` / `.glb`**

  

- **特点：** 体积小、加载快、完美支持 PBR（基于物理的渲染）材质和骨骼动画。
    
      
    
- **场景：** Three.js 前端开发、网页 3D 展厅、元宇宙网页端。
    
      
    

**2. 游戏引擎与动画工业标准：`.fbx`**

  

- **特点：** Autodesk 公司开发的闭源格式。它是目前 3D 软件之间互导最强大的桥梁。能够完美保留复杂的骨骼蒙皮、多套动画数据、复杂的节点关系。
    
      
    
- **场景：** 导入 Unity、Unreal Engine 等游戏引擎，或者在 Blender、Maya、3d Max 之间协同制作游戏资产。
    
      
    

**3. 最经典的通用老前辈：`.obj`**

  

- **特点：** 极其古老的纯文本格式，兼容性全宇宙第一（连操作系统的自带查看器都能秒开）。但它**不支持任何动画和骨架**，而且需要额外带一个 `.mtl` 尾巴文件来记录极其简陋的基础颜色。
    
      
    
- **场景：** 纯静态场景、不需要复杂光影的建筑白模、不同软件间最基础的模型轮廓转移。
    
      
    

**4. 3D 打印与工业制造：`.stl`**

  

- **特点：** 也就是少侠之前下载那个 57MB 的大卫雕像格式。它只记录物体的表面三角形网格，**绝对不包含任何颜色、材质或光影信息**。
    
      
    
- **场景：** CNC 数控机床、3D 打印机切片。前端和游戏开发极度排斥直接使用它。
    
      
    

**5. 苹果与 AR 生态：`.usdz` (USD)**

  

- **特点：** 皮克斯动画工作室开发、苹果大力推行的格式。它本质上是一个免压缩的 zip 包，内部包含高度复杂的场景描述。
    
      
    
- **场景：** iPhone 上的 AR 快速预览（AR Quick Look）、Vision Pro 开发。
    
      
    

在前端领域做 3D 博物馆或数据可视化，死死盯住 `.glb` 这一种格式就足够通关了。
