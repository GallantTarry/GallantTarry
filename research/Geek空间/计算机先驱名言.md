# 计算机先驱名言 

---

> **"The three chief virtues of a programmer are: Laziness, Impatience and Hubris."**
> —— 程序员的三大美德：懒惰、急躁、傲慢。

**Larry Wall**（Perl 语言发明者）
**💡 解读**：懒惰让你想尽办法写自动化脚本来省事；急躁让你受不了慢吞吞的程序而去优化性能；傲慢让你写出不容别人挑刺的健壮代码。这属于极客最高级的自黑与自洽。

---

> **"Always code as if the guy who ends up maintaining your code will be a violent psychopath who knows where you live."**
> —— 写代码时请设想一下，最终维护你代码的那个人，是个知道你住在哪里的暴力精神病患者。

**John Woods**（资深程序员）
**💡 解读**：编程界的“达摩克利斯之剑”。劝诫大家多写注释、规范命名、少挖坑。不然你的接盘侠可能真的会顺着网线来砍你。

---

> **"Code is like humor. When you have to explain it, it’s bad."**
> —— 代码就像讲笑话。如果还需要你去解释，那它就是个烂笑话（烂代码）。

**Cory House**（前端架构师）
**💡 解读**：好代码本身就是最好的注释（Self-documenting）。如果你需要写一大堆注释来解释这段代码在干嘛，通常意味着代码逻辑本身就该重构了。

---

> **"I call it my billion-dollar mistake. It was the invention of the null reference in 1965."**
> —— 我把它叫做我的“十亿美元错误”。那就是在 1965 年发明了 Null 引用。

**Tony Hoare**（图灵奖得主，快速排序发明者）
**💡 解读**：`NullPointerException`（空指针异常）是无数程序员的噩梦。大佬晚年亲自下场认错，为无数因为 `undefined is not a function` 崩溃的开发者提供了极大的情绪价值。

---

> **"Any application that can be written in JavaScript, will eventually be written in JavaScript."**
> —— 任何可以用 JavaScript 编写的应用，最终都会用 JavaScript 编写。

**Jeff Atwood**（Stack Overflow 联合创始人）
**💡 解读**：著名的“Atwood 定律”。前端界用来“一统天下”的霸气宣言，从网页到服务端（Node.js），从桌面端（Electron）到移动端（React Native），甚至你的 VS Code，确实做到了“无孔不入”。

---

> **"First, solve the problem. Then, write the code."**
> —— 先解决问题，再写代码。

**John Johnson**（软件工程师）
**💡 解读**：萌新最容易犯的错误就是一上来就噼里啪啦敲键盘，写到一半发现逻辑不通全部推翻。真正的老手，大部分时间都花在想清楚逻辑和画草图上，敲键盘只是最后的“翻译”工作。

---

> **"People who are really serious about software should make their own hardware."**
> —— 真正在乎软件的人，应该自己制造硬件。

**Alan Kay**（面向对象编程之父，图灵奖得主）
**💡 解读**：乔布斯生前最爱引用的名言之一，这也是苹果公司软硬一体化生态（从 iOS 到 M 系列芯片）的终极思想基石。

---

> **"Data dominates. If you've chosen the right data structures and organized things well, the algorithms will almost always be self-evident."**
> —— 数据结构压倒一切。如果你选对了数据结构并组织良好，算法几乎总是不言自明的。

**Rob Pike**（Go 语言联合创作者，Unix 先驱）
**💡 解读**：Linux 之父 Linus 也表达过完全一致的观点（烂程序员关心代码，好程序员关心数据结构）。这是程序员脱离“语法死记硬背”，真正进入“系统架构”境界的核心顿悟。

---

> **"A language that doesn't affect the way you think about programming, is not worth knowing."**
> —— 一种不改变你编程思维方式的语言，不值得去学。

**Alan Perlis**（首届图灵奖得主）
**💡 解读**：为什么用惯了 Java 还要去看看 Rust 或 Lisp？因为换一门语言，本质上是换一种看待世界和解决问题的底层哲学。

---

> **"Talk is cheap. Show me the code."**
> —— 废话少说，放码过来。

**Linus Torvalds**（Linux 与 Git 之父）
**💡 解读**：专治各种在社区里光说不练、纸上谈兵的行为，是极客圈最硬核的沟通准则。

---

> **"Life is short, you need Python."**
> —— 人生苦短，我用 Python。

**Bruce Eckel**（《C++编程思想》作者）
**💡 解读**：最初是对 Python 极简哲学的赞美，后来成了整个 Python 社区风靡全球的接头暗号。

---

> **"Premature optimization is the root of all evil."**
> —— 过早的优化是万恶之源。

**Donald Knuth**（算法宗师，《计算机程序设计艺术》作者）
**💡 解读**：警告程序员在没有摸清系统真正的性能瓶颈前，不要瞎折腾细枝末节的“炫技式”优化。

---

> **"There are only two hard things in Computer Science: cache invalidation and naming things."**
> —— 计算机科学中只有两件难事：缓存失效和命名。

**Phil Karlton**（Netscape 首席架构师）
**💡 解读**：一针见血地戳中了无数开发者的痛点——有时候给一个变量起个准确的名字，真的比写个复杂的算法还掉头发。

---

> **"There are only two kinds of languages: the ones people complain about and the ones nobody uses."**
> —— 世界上只有两种编程语言：天天被人骂的，和根本没人用的。

**Bjarne Stroustrup**（C++ 之父）
**💡 解读**：完美反击了所有对 C++ 复杂度的吐槽，也一语道破了开发者天天痛骂 JavaScript、Java 却依然离不开它们的真相。

---

> **"Any fool can write code that a computer can understand. Good programmers write code that humans can understand."**
> —— 任何傻瓜都能写出计算机看得懂的代码。优秀的程序员写出的是人能看懂的代码。

**Martin Fowler**（软件架构大师）
**💡 解读**：直击代码可维护性的本质：代码主要是写给人看的，只是顺便在机器上运行一下。

---

> **"Debugging is twice as hard as writing the code in the first place. Therefore, if you write the code as cleverly as possible, you are, by definition, not smart enough to debug it."**
> —— 调试代码比写代码难一倍。所以，如果你写代码时耍尽小聪明，按定义，你就不具备调试它的智商了。

**Brian Kernighan**（C 语言与 Unix 先驱）
**💡 解读**：劝告大家少写晦涩难懂的“天书”代码，否则出了 Bug 你自己都修不好。

---

> **"Measuring programming progress by lines of code is like measuring airplane building progress by weight."**
> —— 用代码行数来衡量开发进度，就像用重量来衡量造飞机的进度一样扯淡。

**Bill Gates**（微软创始人）
**💡 解读**：反击奇葩 KPI 考核和外行指导内行的绝佳金句。

---

> **"If debugging is the process of removing software bugs, then programming must be the process of putting them in."**
> —— 如果说调试是把软件 Bug 移除的过程，那编程一定就是把 Bug 放进去的过程。

**Edsger W. Dijkstra**（图灵奖得主）
**💡 解读**：幽默又精辟地总结了程序员日常“疯狂制造问题然后再解决问题”的死循环。

---

> **"Make it work, make it right, make it fast."**
> —— 先跑起来，再变正确，最后变快。

**Kent Beck**（敏捷开发与极限编程先驱）
**💡 解读**：最为务实的工程化开发节奏，专治程序员的完美主义拖延症。
