# GitHub 网页版的工作流如何使用？

掌握了 GitHub 网页版的工作流，你就可以随时随地参与任何开源项目，或者安全地管理自己的代码了。

这是一份纯基于 **GitHub 网页端**的完整实战通关教程，我们按时间顺序分为五个阶段：

### 阶段一：拿到别人的项目（Fork）

这是你“复制”别人代码库的第一步。

1. **找到目标仓库：** 在 GitHub 上打开你想参与的原作者项目主页（比如 `CharlesPikachu/musicdl`）。
    
2. **点击 Fork：** 在页面右上角，找到并点击 **“Fork”** 按钮。
    
3. **确认创建：** 在弹出的页面中，确认所有者（Owner）是你自己的账号，可以直接点击页面底部的 **“Create fork”**。
    
    > **结果：** 几秒钟后，你的账号下就会多出一个一模一样的仓库（例如 `GallantTarry/musicdl`）。这就是你的私人副本。
    

### 阶段二：开工前的准备（Sync Fork）

为了防止代码冲突，每次开始写新代码前，都要确保你的副本是最新的。

1. **进入你的仓库：** 确保你在自己 Fork 出来的项目主页。
    
2. **同步原作者代码：** 在代码列表的右上方，找到 **“Sync fork”** 下拉菜单。
    
3. **点击更新：** 如果显示你的分支落后（behind），点击 **“Update branch”**。如果显示“This branch is up to date”，说明已经是最新，无需操作。
    

### 阶段三：创建独立工作区（新建分支 Branch）

绝对不要直接在 `master`（或 `main`）主分支上修改代码，永远为你每一次的修改建一个新分支。

1. **展开分支菜单：** 点击左上角显示着 `master`（或 `main`）的下拉按钮。
    
2. **输入新分支名：** 在搜索框里输入你想要的分支名字（比如 `patch-1` 或 `fix-bug`）。
    
3. **确认创建：** 在下拉列表的最下方，会出现一行字提示 **“Create branch: patch-1 from 'master'”**。点击这行字，新分支就建好了，并且页面会自动切换到这个新分支。
    

### 阶段四：修改代码并保存（Commit）

现在你可以在自己的平行宇宙里大胆修改了。

1. **找到文件并编辑：** 点击进入你想修改的代码文件，点击文件内容右上角的 **铅笔图标（Edit this file）** 进入编辑模式。
    
2. **进行修改：** 在网页编辑器里修改你的代码。
    
3. **提交更改（Commit）：**
    
    - 点击页面右上角的 **“Commit changes...”** 按钮。
        
    - 在弹出的对话框中，写一句简短的总结（比如“修复了下载音乐失败的bug”）。
        
    - 确保选择的是直接提交到你刚刚创建的当前分支（如 `patch-1`）。
        
    - 点击绿色的 **“Commit changes”** 按钮。
        

### 阶段五：合并分支（Pull Request / PR）

代码改完且测试没问题后，你需要把代码“合并”回去。这里分为两种情况：

#### 情况 A：只合并给自己（更新你自己的主分支）

如果你只是想把 `patch-1` 的修改合并到你自己的 `master` 里。

1. 点击顶部导航栏的 **“Pull requests”** 标签。
    
2. 点击绿色的 **“New pull request”** 按钮。
    
3. **极其重要的一步：调整对比的分支！**
    
    - 左边的 `base repository` 必须选**你自己的仓库**，`base` 选你的 `master`。
        
    - 右边的 `compare` 选你的新分支 `patch-1`。
        
4. 点击 **“Create pull request”**，填写说明后再次点击创建。
    
5. 在随后出现的页面底部，点击 **“Merge pull request”**，然后确认。你的修改就成功合入自己的主分支了！
    

#### 情况 B：贡献给原作者（向上游提交 PR）

如果你觉得你的修改对所有人都有用，想合并到官方项目中。

1. 回到你的仓库主页，GitHub 通常会在顶部自动弹出一个醒目的黄色提示框，显示你刚刚推送了分支，旁边有一个 **“Compare & pull request”** 的绿色按钮，直接点击它。
    
2. **检查合并方向：**
    
    - 左边的 `base repository` 应该是**原作者的仓库**，`base` 是原作者的主分支。
        
    - 右边的 `compare` 是你修改过的分支 `patch-1`。
        
3. **填写详细说明：** 在描述框里向原作者诚恳地解释你为什么要修改、修改了什么逻辑。
    
4. 点击 **“Create pull request”**。
    
    > **结果：** 剩下的就是等待。原作者会收到通知，他审阅后如果觉得写得好，就会点击合并。恭喜你，你就成为这个开源项目的贡献者（Contributor）了！
  拉去请求就是拉取base库的请求，看他能不能给我合并了。
