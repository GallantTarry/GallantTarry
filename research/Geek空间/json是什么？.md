
# json是什么？

  

**JSON（JavaScript Object Notation，JavaScript 对象简谱）** 是一种**基于文本的轻量级数据交换格式**。虽然它最初源于 JavaScript 语言的字面量语法，但它本身是**独立于语言**的，目前几乎所有主流编程语言（Java、Python、C#、C++、Go、PHP、Rust 等）都内置了对 JSON 的解析和生成支持。

  

### 一、 为什么 JSON 会成为行业标准？

在 JSON 普及之前，Web 数据交换主要依赖 **XML（可扩展标记语言）**。与 XML 相比，JSON 具备极其显著的优势：

  

1. **轻量与低传输开销：** JSON 没有繁琐的闭合标签（如 `<name>Jack</name>` 在 JSON 中仅为 `"name": "Jack"`），有效节省网络带宽。
    
      
    
2. **极佳的可读性：** 结构扁平且清晰，人类可以直接阅读和手动编写。
    
      
    
3. **机器解析高效：** 结构紧凑，反序列化为内存对象的速度远快于 DOM/SAX 方式解析 XML。
    
      
    

### 二、 JSON 的语法规则与数据类型

JSON 的语法极其简洁，仅支持以下 **6 种基本数据类型**：

  

JSON

```
{
  "stringKey": "hello",
  "numberKey": 42,
  "booleanKey": true,
  "nullKey": null,
  "arrayKey": [1, 2, 3],
  "objectKey": {
    "nestedKey": "value"
  }
}
```

#### 语法要点概括：

- **结构载体：** 数据在名称/值对（键值对）中，用逗号 `,` 分隔；大括号 `{}` 保存对象，中括号 `[]` 保存数组。
    
      
    
- **严格双引号：** 键名（Key）**必须使用双引号** `""` 包裹。字符串类型的值也必须使用双引号。
    
      
    
- **无末尾逗号（Trailing Comma）：** 数组或对象的最后一个元素后面**不能**加逗号（某些解析器会报错）。
    
      
    

### 三、 JSON 与 JavaScript 对象的区别

很多初学者容易混淆 JSON 字符串与 JavaScript 中的原生对象，它们虽然看起来相似，但有着本质的不同：

  

|**特性维度**|**JSON (数据格式)**|**JavaScript 对象 (内存数据结构)**|
|---|---|---|
|**本质属性**|纯文本字符串|内存中的对象实体|
|**键名限制**|必须加双引号 `""`|可不加引号、单引号或双引号|
|**支持的数据类型**|仅支持上述 6 种数据类型|支持函数 (`function`)、`undefined`、`Symbol` 等|
|**注释支持**|不支持任何注释|支持单行 `//` 和多行 `/* */` 注释|
|**方法定义**|无法包含任何逻辑或函数|可以包含方法和 getter/setter|

### 四、 核心工作流程：序列化与反序列化

在软件开发中，JSON 主要担任不同系统（如前端与后端、微服务与微服务）之间的**传输媒介**。这一过程依赖两个核心动作：

  

1. **序列化（Serialization / Stringify）：** 将内存中的数据对象（如 Java 的 POJO、Python 的 Dict、JS 的 Object）转化为 JSON 格式的纯文本字符串，以便在网络传输或保存至本地文件。
    
      
    - _示例（JavaScript）：_ `JSON.stringify(obj)`
        
          
        
2. **反序列化（Deserialization / Parse）：** 将接收到的 JSON 文本字符串重新解析并还原为本地语言的内存数据对象。
    
      
    - _示例（JavaScript）：_ `JSON.parse(jsonString)`
        
          
        

### 五、 拓展延伸：JSON 的局限性与衍生生态

尽管 JSON 在现代软件架构中占据统治地位，但面对特定的高阶场景，它也存在一些局限，从而推动了相关演进技术的诞生：

  

1. **配置文件场景的痛点与演化：**
    
      
    - **痛点：** JSON 标准不支持注释，且对遗漏或多余的逗号非常敏感，手写维护难度大。
        
          
        
    - **替代方案：** 在复杂配置场景中，开发者常使用 **YAML**（格式更简洁、支持注释与引用）或 **JSON5**（允许注释、单引号、末尾逗号的 JSON 超集）。
        
          
        
2. **高性能与二进制数据场景：**
    
      
    - **痛点：** JSON 是纯文本，在传输海量图片、二进制流或对性能要求极高的实时通信中，文本编解码性能和体积开销较大。
        
          
        
    - **替代方案：**
        
          
        - **BSON (Binary JSON)：** MongoDB 使用的二进制扩展格式，支持更多类型（如 Date、ObjectID），解析速度更快。
            
              
            
        - **Protobuf / MessagePack：** 跨语言的二进制序列化协议，体积更小，序列化速度远超 JSON，常用于 RPC 微服务架构（如 gRPC）。
