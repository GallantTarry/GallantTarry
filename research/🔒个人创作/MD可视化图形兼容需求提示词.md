# MD可视化图形兼容需求提示词

这一路走来确实像打怪升级！我们完美踩中了静态博客搭建中最经典的两个坑：**Markdown 解析引擎的误伤**（空行和缩进导致代码爆红）以及 **SPA 单页应用的安全拦截**（动态插入的 `<script>` 变成死代码）。

  

既然你确定了这种“不改全局配置、直接贴 `.md` 文件”的极简开发流，以后问我要任何可视化图形、交互 UI 或者网页小工具时，为了让我一次性给你完美运行的代码，你只需要在提问时附上这段“暗号（Prompt）”：

  

> **“请为我生成 Docsify 特供版的 HTML/JS 代码。要求：**
> 
> **1. 直接粘贴进 .md 文件使用，不依赖 iframe 或新建文件；**
> 
> **2. 代码内部绝对不能有空行，所有 HTML 标签尽量顶格写（避免被识别为 Markdown 代码块）；**
> 
> **3. 必须使用 `<img src="x" onerror="...">` 的黑魔法来执行 JS 逻辑；**
> 
> **4. CSS 样式和 JS 变量/函数必须加专属前缀，做好作用域隔离。”**
> 
> **5. 要同时适配电脑端和移动端。”**  

### 为什么要注意这四点（原理解释）：

1. **零依赖**：保证你的博客目录依然清爽，不需要为了一个图表去新建一堆 `.html` 杂乱文件。
    
      
    
2. **防 Markdown 误杀**：Markdown 解析器（marked.js）只要一看到空行，就会觉得“HTML 写完了，下面是普通文本”，一看到 4 个空格的缩进，就会把它当成“代码块”。**顶格+无空行**是物理超度这个问题的唯一解。
    
      
    
3. **强行唤醒 JS 引擎**：这是我们的核心黑魔法。因为 Docsify 切换页面是 AJAX 无刷新加载，浏览器为了安全（防 XSS 攻击）会直接阉割掉里面 `<script>` 的执行权限。而 `<img>` 加载失败触发的 `onerror` 是底层 DOM 事件，它能无视这个规则，帮你把休眠的代码“踹醒”。
    
      
    
4. **防污染**：因为代码是直接内联在网页里的，如果我写了一个 `body { background: white; }` 或者通用的 `let timer = 0;`，很容易把你 TuKuai OS 博客的主题样式搞崩，或者和其他页面的脚本打架。加上专属前缀（比如 `wd-xxx`）就相当于把它关在了一个安全的沙盒里。
