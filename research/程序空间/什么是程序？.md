# 什么是程序？


如果用一个通俗的比喻来说：**数据结构是“盛放数据的容器”，而算法是“处理这些数据的方法和步骤”**。图灵奖得主尼克劳斯·维尔特（Niklaus Wirth）曾提出过一个著名的公式：**程序 = 数据结构 + 算法**。没有合适的数据结构，算法就会因为操作繁琐而效率低下；没有算法，数据结构里的数据就只是一堆静止的内存占用。

  

关于“数据结构具体说了哪些内容”，它本质上研究的是**数据在计算机内存中的组织、存储和管理方式**。主要可以划分为以下四大类结构：

  

### 1. 线性结构 (Linear Structures)

数据元素之间是一对一的关系，就像排队一样。

  

- **数组 (Array) 与 链表 (Linked List)：** 这是最基础的两种存储方式。数组在内存中是连续分配的，查询快但增删慢；链表是分散存储通过指针连接的，增删快但查询慢。在处理大量的结构化表格数据（例如读取和解析多行 Excel 记录）时，底层往往就是在数组和链表的动态变体中做选择。
    
      
    
- **栈 (Stack)：** 后进先出（LIFO）。就像叠盘子，最后放上去的盘子最先被拿走。程序中的函数调用、撤销操作（Undo）都依赖栈。
    
      
    
- **队列 (Queue)：** 先进先出（FIFO）。就像超市结账排队。在开发带有物理碰撞、状态交互的像素游戏时，系统的输入指令和物理事件通需要被推入事件队列中，在游戏主循环里逐帧按顺序进行结算处理。
    
      
    

### 2. 树形结构 (Tree Structures)

数据元素之间是一对多的层次关系，就像家族的族谱。

  

- **二叉树 (Binary Tree)、红黑树、B树等：** 它们是为了高效的搜索和排序而诞生的。
    
      
    
- 在实际工程中，树的应用无处不在。比如在一个包含众多模块和嵌套面板的桌面图形界面（GUI）应用中，从主窗口到里面的标签、按钮、文本框，其底层的组织逻辑就是一棵控件树；数据库（如 MySQL）的底层索引结构（B+树）也是树形结构的巅峰应用。
    
      
    

### 3. 散列结构 (Hash Structures)

这也是我们常说的字典或映射，通过哈希函数将数据直接映射到内存地址。

  

- **哈希表 (Hash Table/HashMap)：** 它的核心优势在于极其恐怖的查找速度（理想状态下时间复杂度为 O(1)）。
    
      
    
- 当系统需要处理大量数据的自动化比对、跨表校验关联字段或者快速清洗去重时，哈希表是优化性能、避免系统卡顿的最核心利器。
    
      
    

### 4. 图结构 (Graph Structures)

数据元素之间是多对多的网状关系。

  

- **有向图、无向图、加权图：** 它们由节点（顶点）和连接节点的边组成。
    
      
    
- 常见的应用场景包括网络拓扑结构、社交媒体的好友关系，以及游戏开发中 NPC 的自动寻路系统（例如 A* 寻路算法就是在图结构上运行的）。
    
      
    

简而言之，数据结构教导我们如何根据具体的业务场景，选择最合适的“容器”来装载数据，从而让后续的“算法”跑得更快、更省内存。
