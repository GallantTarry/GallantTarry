# 时间与空间复杂度

**时间复杂度**与**空间复杂度**是衡量算法效率的标尺。它们不以具体的“运行秒数”或“占用字节数”为单位（因为这高度依赖 CPU 算力、编程语言和编译器优化），而是评估**当输入数据规模 $n$ 趋向无穷大时，算法所需执行的基本操作次数与额外内存空间随 $n$ 增长的变化趋势（渐近增长率）**。

  

## 一、 核心基石：大 $O$ 渐近表示法（Big O Notation）

假设某算法处理规模为 $n$ 的数据时，所有代码行的执行总次数为函数 $T(n)$。当 $n$ 极大时，我们只关心 $T(n)$ 增长最快的那个主干部分，并用**大 $O$ 记号**表示为：

  

$$T(n) = O(f(n))$$

### 1. 三种渐近界符号

在算法理论中，描述增长趋势有三个核心符号：

  

- **大 $O$ 符号（$O$，渐近上界）**：表示算法执行时间的**增长上限**（即最坏或一般情况不会比它更慢）。工程开发与面试中提到的复杂度，99% 指的都是大 $O$。
    
      
    
- **大 $\Omega$ 符号（$\Omega$，渐近下界）**：表示算法执行时间的**增长下限**（即最好情况下至少需要这么多时间）。
    
      
    
- **大 $\Theta$ 符号（$\Theta$，渐近紧确界）**：当一个算法的上界 $O$ 与下界 $\Omega$ 同阶时，用 $\Theta$ 表示它的精确增长阶。
    
      
    

### 2. 大 $O$ 推导化简三原则

只要计算出基本操作次数表达式 $T(n)$，即可按以下三步直接写出大 $O$ 复杂度：

  

1. **常数项统一替换为 $1$**：无论固定执行 $1$ 次还是 $10000$ 次，只要执行次数与输入规模 $n$ 无关，时间复杂度一律记为 **$O(1)$**。
    
      
    
2. **只保留最高阶项**：在多项式 $T(n) = 2n^3 + 50n^2 + 100n + 8$ 中，当 $n \to \infty$ 时，$n^3$ 的增长速度远超其余项，因此直接舍弃低阶项 $50n^2 + 100n + 8$。
    
      
    
3. **抹去最高阶项的常数系数**：将 $2n^3$ 的系数 $2$ 抹去，最终记为 **$O(n^3)$**。
    
      
    

## 二、 时间复杂度（Time Complexity）全解

### 1. 代码复杂度的四条计算法则

- **顺序结构（加法法则）**：多段代码顺序执行时，总复杂度等于耗时最长的那一段。即 $O(f(n)) + O(g(n)) = O(\max(f(n), g(n)))$。
    
      
    
- **嵌套循环（乘法法则）**：循环套循环时，内外层复杂度相乘。即 $O(f(n)) \times O(g(n)) = O(f(n) \cdot g(n))$。
    
      
    
- **条件分支（取最大值）**：`if-else` 分支结构中，取所有可能分支里复杂度最高的一支作为整体上界。
    
      
    
- **递归调用（递归树法）**：$\text{总时间复杂度} = \text{递归调用总次数} \times \text{单次递归内部的基本操作复杂度}$。
    
      
    

### 2. 七大常见时间复杂度阶梯（从快到慢）

当数据规模 $n$ 扩大时，不同复杂度阶梯的性能差距呈断崖式拉开。常见的增长率排序为：

  

$$O(1) \lt O(\log n) \lt O(n) \lt O(n \log n) \lt O(n^2) \lt O(2^n) \lt O(n!)$$

|**复杂度阶**|**中文名称**|**n=105 时的约算次数**|**典型算法与操作场景**|**工程可用性评估**|
|---|---|---|---|---|
|**$O(1)$**|常数阶|$1$ 次|数组下标随机访问、哈希表键值查询、栈的入栈/出栈|极佳，瞬间完成|
|**$O(\log n)$**|对数阶|$\approx 17$ 次|二分查找、平衡二叉搜索树（红黑树/AVL）查找、快速幂|极佳，仅次于 $O(1)$|
|**$O(n)$**|线性阶|$10^5$ 次|单层数组遍历、链表查找、双指针滑动窗口|优秀，处理百万级数据无压力|
|**$O(n \log n)$**|线性对数阶|$\approx 1.7 \times 10^6$ 次|归并排序、快速排序（平均）、堆排序|良好，通用比较排序的理论天花板|
|**$O(n^2)$**|平方阶|$10^{10}$ 次（超时）|冒泡/插入/选择排序、双层嵌套全量比对|仅适用于 $n \le 5000$ 的小规模数据|
|**$O(2^n)$**|指数阶|天文数字|未剪枝的斐波那契递归、集合的所有子集枚举|仅适用于 $n \le 25$ 的极小规模数据|
|**$O(n!)$**|阶乘阶|天文数字|全排列搜索、暴力求解旅行商问题（TSP）|仅适用于 $n \le 10$ 的微型数据|

#### 典型代码案例剖析

**（1）对数阶 $O(\log n)$ —— 为什么底数可以直接省略？**

观察以下倍增循环代码：

  

Java

```
int i = 1;
while (i < n) {
    i = i * 2; // 每次循环 i 翻倍
}
```

假设循环执行了 $k$ 次后终止，则满足 $2^k \ge n$，求解得 $k = \log_2 n$。

如果将代码改为 `i = i * 3`，则执行次数为 $\log_3 n$。根据对数换底公式：

  

$$\log_3 n = \frac{\log_2 n}{\log_2 3} = \left(\frac{1}{\log_2 3}\right) \cdot \log_2 n$$

由于 $\frac{1}{\log_2 3}$ 是一个固定常数，在忽略常数系数的原则下，$\log_2 n$ 与 $\log_3 n$ 完全等价，因此统一简记为 **$O(\log n)$**。

  

**（2）线性对数阶 $O(n \log n)$ —— 外层线性、内层倍增**

  

Java

```
for (int i = 0; i < n; i++) {       // 外层执行 n 次 -> O(n)
    int j = 1;
    while (j < n) {                 // 内层执行 log n 次 -> O(log n)
        j = j * 2;
    }
}
// 根据乘法法则：总时间复杂度 = O(n) * O(log n) = O(n log n)
```

### 3. 最好、最坏、平均与均摊时间复杂度

同一个算法面对不同形态的输入数据时，耗时可能截然不同。因此引入四个评估维度：

  

- **最好情况时间复杂度（Best Case）**：在最理想输入下的耗时（例如在数组中查找目标元素，第 1 个位置就命中，为 $O(1)$）。
    
      
    
- **最坏情况时间复杂度（Worst Case）**：在最极端输入下的耗时（例如遍历到数组末尾才找到或根本不存在，为 $O(n)$）。**工程底线设计以最坏复杂度为准。**
    
      
    
- **平均情况时间复杂度（Average Case）**：综合所有可能输入出现的概率，计算加权数学期望。
    
      
    
- **均摊时间复杂度（Amortized Complexity）**：
    
    以动态数组（如 Java 的 `ArrayList` 或 Python 的 `list`）尾部追加元素 `add()` 为例：
    
      
    - 当底层数组还有剩余容量时，直接放入末尾，耗时 **$O(1)$**。
        
          
        
    - 当容量满时（假设当前容量为 $n$），触发自动扩容：申请 $2n$ 大小的新数组，并将原数组中 $n$ 个元素拷贝过去，仅这一步耗时 **$O(n)$**。
        
          
        
    - **摊还分析（Amortized Analysis）**：每经过 $n$ 次廉价的 $O(1)$ 插入，才会触发 1 次昂贵的 $O(n)$ 拷贝。把这 1 次 $O(n)$ 的代价平摊到前 $n$ 次操作上，平均每次插入分摊到的额外成本仅为常数级，因此动态数组尾部插入的**均摊时间复杂度为 $O(1)$**。
        
          
        

## 三、 空间复杂度（Space Complexity）全解

### 1. 输入空间 vs. 辅助空间

算法运行时的内存占用分为两部分：

  

1. **输入数据本身占用的空间**：由调用方传入，算法无法改变。
    
      
    
2. **辅助空间（Auxiliary Space）**：算法为了完成计算而**额外临时开辟**的内存空间。
    
      
    

在日常算法分析中，我们说的**空间复杂度 $S(n)$ 默认指的就是“辅助空间”的增长趋势**。

  

### 2. 额外空间的三大隐蔽来源

分析空间复杂度时，需要重点排查以下三处内存开销：

  

1. **基础变量与指针**：申请固定数量的局部变量（如 `int count = 0`、双指针 `left`/`right`），占用空间不随 $n$ 变化，记为 **$O(1)$**，这类算法称为**原地算法（In-place Algorithm）**。
    
      
    
2. **动态分配的堆内存**：在算法内部显式 `new` 出来的数组、哈希表（`HashMap`）、链表节点等。若创建的数组长度为 $n$，则空间复杂度为 **$O(n)$**；若创建 $n \times n$ 的二维动态规划矩阵，则为 **$O(n^2)$**。
    
      
    
3. **递归调用栈空间（最容易漏算）**：每次函数递归调用自身时，系统都必须在内存栈（Call Stack）中压入一个栈帧（Stack Frame）以保存局部变量、参数和返回地址。
    
      
    
    > **核心定律：** 递归算法的空间复杂度 $\ge O(\text{最大递归调用深度})$。
    > 
    >   
    

### 3. 递归空间复杂度的经典陷阱对比

**案例 A：单链递归求和 —— 时间 $O(n)$，空间也是 $O(n)$**

  

Java

```
int sum(int n) {
    if (n <= 1) return 1;
    return n + sum(n - 1);
}
```

虽然代码里没有 `new` 任何数组，但从 `sum(n)` 一路调用到 `sum(1)`，调用栈同时堆积了 $n$ 层未返回的栈帧，最大栈深度为 $n$，因此空间复杂度为 **$O(n)$**。

  

**案例 B：无记忆化斐波那契递归 —— 时间 $O(2^n)$，但空间仅为 $O(n)$**

  

Java

```
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
```

- **时间复杂度**：递归树呈二叉树状分裂，节点总数约为 $2^n$，因此时间复杂度为 **$O(2^n)$**。
    
      
    
- **空间复杂度**：很多初学者误以为空间也是 $O(2^n)$。实际上，代码执行是**深度优先（先算完左分支 `fib(n-1)` 并释放栈帧后，再进入右分支 `fib(n-2)`）**。内存中同一时刻存活的栈帧数量取决于**递归树的最大高度 $n$**，因此空间复杂度仅为 **$O(n)$**。

## 五、 工程核心思维：时间与空间的权衡（Time-Space Tradeoff）

在实际软件架构与算法优化中，时间和空间往往像天平的两端，可以根据硬件条件互相转化：

  

1. **以空间换时间（现代软件开发的主流策略）**
    
    由于现代服务器内存与磁盘成本较低，而用户对响应延迟极度敏感，工程上常通过增加内存消耗来换取极致的执行速度：
    
      
    - **哈希表降维**：在经典的“两数之和（Two Sum）”问题中，暴力双层循环需要 $O(n^2)$ 时间与 $O(1)$ 空间；若开辟一个 $O(n)$ 空间的哈希表记录已遍历元素，可将查找每次配对数的时间从 $O(n)$ 降至 $O(1)$，整体时间复杂度直接降至 **$O(n)$**。
        
          
        
    - **记忆化搜索与动态规划（DP）**：将递归过程中重复计算的子问题结果缓存到数组或哈希表中，使斐波那契数列求解从 $O(2^n)$ 指数级直接降为 **$O(n)$** 线性级。
        
          
        
    - **工程实例**：数据库建立 B+ 树索引、Redis 内存缓存、浏览器页面缓存。
        
          
        
2. **以时间换空间（内存受限或超大规模数据场景）**
    
    在嵌入式设备、内核开发或海量数据超出内存上限时，必须严控空间占用：
    
      
    - **原地算法改写**：在动态规划中使用“滚动数组”技巧，只保留上一行的状态，将二维 DP 表的 $O(n^2)$ 空间压缩至 $O(n)$ 甚至 $O(1)$。
        
          
        
    - **位运算与外部排序**：使用位图（BitMap）压缩布尔状态，或在内存不足以装下大文件时采用多路外部归并排序（牺牲磁盘 I/O 时间换取极低内存占用）。

> **核心总结：** 分析时间复杂度紧盯**循环次数与递归调用总次数**，分析空间复杂度紧盯**显式开辟的集合大小与隐式递归调用栈的最大深度**。在工程实践中，优先将 $O(n^2)$ 及以上的高阶算法通过**哈希表（空间换时间）**、**二分查找**或**双指针/滑动窗口**优化至 $O(n \log n)$ 或 $O(n)$ 级别，是突破性能瓶颈最有效的手段。
