# http 和 https有什么区别？


HTTP 和 HTTPS 的核心区别可以用四个字概括：**安全加密**。

  

简单来说，HTTP 是互联网上应用最为广泛的一种网络协议，用于在 Web 浏览器和网站服务器之间传递信息；而 HTTPS 则是 HTTP 的“安全升级版”，它在 HTTP 的基础之上加入了 SSL/TLS 协议，为数据传输建立了一条加密隧道。

  
## 核心差异对比

|**维度**|**HTTP (HyperText Transfer Protocol)**|**HTTPS (HyperText Transfer Protocol Secure)**|
|---|---|---|
|**数据传输状态**|**明文传输**。任何人只要能在网络节点（如路由器、运营商）截获数据包，就能直接看到密码、交易信息等原始内容。|**密文传输**。数据在发送前会被加密，即便被中间人截获，看到的也是一堆毫无意义的乱码。|
|**默认端口**|`80`|`443`|
|**证书需求**|无需任何证书，服务器配置完成后即可直接使用。|需要向数字证书认证机构（CA）申请 SSL/TLS 证书。|
|**连接建立过程**|仅需 TCP 三次握手即可建立连接并开始传输数据。|在 TCP 三次握手之后，还需要进行复杂的 **SSL/TLS 握手**（交换密钥、验证证书）才能开始传输数据。|
|**浏览器标识与 SEO**|现代浏览器（如 Chrome）会将 HTTP 网站标记为“不安全”；搜索引擎（如 Google）会降低其搜索排名。|浏览器地址栏会显示“安全锁”图标；搜索引擎会给予更高的权重倾斜。|


## 拓展深度：HTTPS 是如何实现加密的？

HTTPS 的安全性并不是单一技术的产物，它巧妙地结合了**对称加密**、**非对称加密**和**哈希算法**的优势：

  

1. **非对称加密（验证身份与交换密钥）**：
    
    在 TLS 握手阶段，服务器会向客户端发送自己的公钥（包含在 CA 证书中）。客户端用这个公钥加密一个随机生成的“会话密钥”（Session Key）并发送给服务器。因为只有服务器拥有对应的私钥，所以世界上只有服务器能解密拿到这个“会话密钥”。这保证了密钥在传输过程中的绝对安全。
    
      
    
2. **对称加密（高效传输数据）**：
    
    非对称加密极其消耗系统算力，不适合用来加密海量的网页数据。因此，当双方在握手阶段安全地交换了上述的“会话密钥”后，接下来的所有 HTTP 报文都会使用这个“会话密钥”进行**对称加密**。对称加密速度极快，保证了网页的加载性能。
    
      
    
3. **哈希算法（保证数据完整性）**：
    
    为了防止数据在传输过程中被黑客偷偷篡改（比如把转账金额从 100 改成 10000），HTTPS 还会对数据加上 MAC（消息认证码）。客户端收到数据后重新计算哈希值，如果与收到的哈希值不一致，就说明数据被动过手脚，连接会立刻中断。
