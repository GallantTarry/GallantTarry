# 彻底吃透 C 语言指针：从内存模型到工程实战

很多人觉得 C 语言指针像玄学，根源在于试图用“语法规则”去死记硬背，而不是用**硬件内存模型**去理解它。

只要建立起一个画面，指针就会瞬间变得透明：**内存是一排按字节编号的连续格子，而指针，就是一个专门用来存放“门牌号”的普通变量。**

---

## 一、底层地基：内存、地址与指针的本质

假设你在代码里写下这两行：

```c
int a = 42;
int *p = &a;
```

在 64 位计算机的内存里，真实发生的事情长这样：

```text
  内存地址        存储的值          变量名 & 说明
+----------+   +----------+
|  0x1000  |   |    42    |  <--  a (占用 4 字节: 0x1000 ~ 0x1003)
+----------+   +----------+
     ^
     | (指向)
     +----------------+
                      |
+----------+   +------+---+
|  0x2000  |   |  0x1000  |  <--  p (占用 8 字节，里面存的是 a 的首地址)
+----------+   +----------+
```

记住三个最基本的动作：
1. **取地址（`&`）**：拿到变量的门牌号。`&a` 的结果是 `0x1000`。
2. **定义指针（`*`）**：声明里的 `*` 只是告诉编译器“这是一个指针变量”。`int *p` 表示 `p` 存的是一个 `int` 对象的地址。
3. **解引用（`*`）**：表达式里的 `*` 表示“顺着门牌号找过去”。`*p = 100;` 会直接把 `0x1000` 里的 `42` 改成 `100`。

### 灵魂拷问：既然所有指针都只存地址，为什么还要分 `int *` 和 `char *`？

在 64 位系统下，`sizeof(char *)`、`sizeof(int *)`、`sizeof(double *)` **全部都是 8 字节**。指针前面的类型，决定的不是指针自己的大小，而是两件生死攸关的事：

1. **解引用时读几个字节、怎么解析**：对 `int *` 执行 `*p`，CPU 会从 `0x1000` 开始连续读 4 字节，按有符号整数解析；对 `char *` 则只读 1 字节。
2. **指针加减时的步长（Stride）**：`p + 1` 不是地址加 1，而是地址加上 `sizeof(*p)`。
    - `char *p`：`p + 1` 往后跳 **1 字节**。
    - `int *p`：`p + 1` 往后跳 **4 字节**。
    - `double *p`：`p + 1` 往后跳 **8 字节**。

## 二、指针算术与数组退化：解开 `a` 与 `&a` 的终极谜团

C 语言里，数组和指针有着极深的血缘关系，但**数组绝对不等于指针**。

### 1. 下标运算符的本质
在编译器眼里，`arr[i]` 只是 `*(arr + i)` 的语法糖。甚至因为加法满足交换律，`i[arr]` 也能合法通过编译（虽然写进生产代码会被同事打死）。

### 2. 数组名退化（Array Decay）
在绝大多数表达式中，数组名 `arr` 会自动**退化为指向其首元素的指针**（类型为 `int *`）。但有两个绝对例外：
- **`sizeof(arr)`**：计算的是**整个数组**占用的总字节数，不会退化。
- **`&arr`**：取的是**整个数组**的地址，类型为 `int (*)[N]`（数组指针）。

看一段经典的对比代码：

```c
#include <stdio.h>

int main(void) {
    int arr[4] = {10, 20, 30, 40};

    printf("arr     = %p\n", (void *)arr);
    printf("arr + 1 = %p  (前进 4 字节，跳过 1 个 int)\n", (void *)(arr + 1));

    printf("&arr     = %p\n", (void *)&arr);
    printf("&arr + 1 = %p  (前进 16 字节，跳过整个数组)\n", (void *)(&arr + 1));
    return 0;
}
```

> **核心结论**：`arr` 和 `&arr` 打印出来的**数值完全相同**，但它们的**类型不同**，导致 `+ 1` 时的步长天差地别。

### 3. 一句话分清“指针数组”与“数组指针”
看优先级：`[]` 的优先级高于 `*`。
- **指针数组** `int *p[3]`：`p` 先和 `[3]` 结合，本质是个**数组**，里面装了 3 个 `int *` 指针。
- **数组指针** `int (*p)[3]`：括号强行让 `p` 先和 `*` 结合，本质是个**指针**，指向一个长度为 3 的 `int` 数组（常用于二维数组传参）。

## 三、`const`、`void *` 与三大内存杀手

### 1. `const` 修饰指针：口诀“左定值，右定向”
判断 `const` 锁住了谁，只看它在 `*` 的左边还是右边：

| 声明写法 | `const` 位置 | 含义 | 允许修改 `*p`？ | 允许修改 `p`？ |
| :--- | :--- | :--- | :---: | :---: |
| `const int *p` / `int const *p` | `*` 左边 | 指向常量的指针（常量指针） | ❌ 禁止 | ✅ 允许 |
| `int * const p` | `*` 右边 | 指针本身是常量（指针常量） | ✅ 允许 | ❌ 禁止 |
| `const int * const p` | 左右都有 | 双重锁定 | ❌ 禁止 | ❌ 禁止 |

### 2. 泛型指针 `void *`
`void *` 是 C 语言实现**泛型编程**的基石（比如 `malloc`、`memcpy`、`qsort`）。它可以无损接收任何类型的指针，但因为丢失了类型信息，**不能直接解引用，也不能直接做加减运算**，必须先强转为具体类型（通常是 `unsigned char *` 按字节操作）。

```c
#include <stddef.h>

// 通用内存交换：不限类型，只要传地址和字节数
void generic_swap(void *a, void *b, size_t size) {
    unsigned char *pa = (unsigned char *)a;
    unsigned char *pb = (unsigned char *)b;
    while (size--) {
        unsigned char tmp = *pa;
        *pa++ = *pb;
        *pb++ = tmp;
    }
}
```

### 3. 三大内存杀手与防坑守则
1. **野指针（Wild Pointer）**：声明了指针却没初始化，里面装着随机垃圾地址。
    - **解法**：定义时立刻初始化，暂时没指向就赋值 `NULL`。
2. **悬空指针（Dangling Pointer）**：指向的内存已经被 `free` 释放，或者指向了已经返回的函数局部变量（栈帧已销毁）。
    - **解法**：`free(p)` 之后立刻补一句 `p = NULL;`；绝对不要返回局部变量的地址。
3. **缓冲区越界（Out-of-Bounds）**：指针算术走出了合法内存范围，悄悄踩坏相邻变量或触发段错误（Segmentation Fault）。
    - **解法**：传递数组指针时，永远把长度 `size_t len` 一并传进去。

## 四、指针与字符串、结构体、函数

### 1. 字符串的经典陷阱
```c
char s1[] = "hello";        // 存在栈上：是把字面量拷贝了一份进数组，可以修改 s1[0] = 'H'
const char *s2 = "hello";   // 指向只读数据段 (.rodata)：强行修改 *s2 = 'H' 直接段错误崩溃
```
> **工程习惯**：指向字符串字面量的指针，永远加上 `const`，让编译器在编译期帮你拦住非法写入。

### 2. 结构体指针与 `->`
当结构体很大时，传值会触发整块内存拷贝，效率极低；工程中几乎一律传指针：

```c
typedef struct {
    int x;
    int y;
} Point;

void move_point(Point *p, int dx, int dy) {
    // p->x 完全等价于 (*p).x，注意括号不能省，因为 . 的优先级高于 *
    p->x += dx;
    p->y += dy;
}
```

### 3. 传值 vs 传址
C 语言的参数传递**永远只有值传递**。所谓的“传址”，本质上是**把指针的值（内存地址）拷贝一份传进函数**。函数通过这份地址拷贝解引用，从而精准修改外部变量。

## 五、二级指针与堆内存管理

### 1. 什么时候必须用二级指针 `T **`？
记住一条铁律：**如果你想在函数内部修改外部变量的值，就传它的指针；如果你想在函数内部修改外部“一级指针”的指向，就必须传它的二级指针。**

```text
   pp (int **)          p (int *)           a (int)
+--------------+    +--------------+    +------------+
|  0x2000      |--->|  0x1000      |--->|     42     |
+--------------+    +--------------+    +------------+
  地址: 0x3000        地址: 0x2000        地址: 0x1000
```

经典场景：在函数里给外部指针动态分配内存，或者像 Linus 那样用二级指针无分支删除单链表头节点。

```c
#include <stdlib.h>

// 正确写法：通过二级指针把新分配的堆地址写回外部的 ptr
int alloc_buffer(char **out_buf, size_t size) {
    char *tmp = (char *)malloc(size);
    if (!tmp) return -1;
    *out_buf = tmp;
    return 0;
}
```

### 2. 堆内存管理四件套的安全姿势
- **`malloc(size)`**：分配未初始化的原始内存，速度最快。
- **`calloc(n, size)`**：分配并**全部清零**，防未初始化垃圾值。
- **`realloc(ptr, new_size)`**：扩容/缩容。**防坑点**：千万不要直接写 `p = realloc(p, new_size);`，一旦扩容失败返回 `NULL`，原来的地址就丢了（直接内存泄漏）。必须用临时指针接住：

```c
int *tmp = (int *)realloc(p, new_size);
if (tmp != NULL) {
    p = tmp;
}
```

## 六、高阶实战：函数指针、回调与右左法则

代码编译后也躺在内存里（代码段 `.text`），每个函数都有自己的入口地址——指向这个地址的指针，就是**函数指针**。

### 1. 转移表（Dispatch Table）：用函数指针消灭冗长的 `switch-case`

```c
#include <stdio.h>

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }
int mul(int a, int b) { return a * b; }

// 定义函数指针类型别名，代码瞬间清爽
typedef int (*OpFunc)(int, int);

int main(void) {
    // 函数指针数组（转移表）
    OpFunc ops[] = { add, sub, mul };

    int cmd = 2; // 比如 0=加, 1=减, 2=乘
    printf("结果: %d\n", ops[cmd](6, 7)); // 输出 42
    return 0;
}
```

### 2. 终极武器：用“右左法则”拆解任何变态声明
遇到复杂的 C 声明，从**变量名**出发，遵循**先向右看、碰壁（`)` 或末尾）再向左看、遇括号跳出**的规则：

以 C 标准库著名的 `signal` 函数为例：
```c
void (*signal(int sig, void (*func)(int)))(int);
```

拆解步骤：
1. 找到名字 `signal`。
2. 向右看是 `(int sig, void (*func)(int))` → `signal` 是一个**函数**，接收一个 `int` 和一个函数指针 `func`。
3. 向左看是 `*` → 它的返回值是一个**指针**。
4. 跳出括号向右看是 `(int)` → 这个指针指向一个接收 `int` 参数的**函数**。
5. 向左看是 `void` → 该函数返回 `void`。

**人话翻译**：`signal` 是一个函数，它接收信号编号和一个回调函数，并返回“上一次注册的那个回调函数指针”。用 `typedef` 重写就会清晰十倍：

```c
typedef void (*sighandler_t)(int);
sighandler_t signal(int sig, sighandler_t func);
```

## 终极速查表

| 写法 | 一句话本质 | 典型用途 |
| :--- | :--- | :--- |
| `int *p` | 一级指针 | 指向普通变量、遍历一维数组 |
| `const int *p` | 常量指针（左定值） | 函数只读入参，防止误改数据 |
| `void *p` | 泛型指针 | 通用内存操作（`memcpy`、`qsort`） |
| `int *p[N]` | 指针数组 | 存放多个字符串（如 `char *argv[]`） |
| `int (*p)[N]` | 数组指针 | 指向二维数组的行 |
| `int **pp` | 二级指针 | 在函数内修改外部指针、链表无分支删除 |
| `int (*fp)(int)` | 函数指针 | 回调机制、状态机、转移表 |
