# 网页图标全端适配与规范指南

> **核心结论：** 现代网页图标（Favicon）无需堆砌十几种尺寸的图片，只需遵循 **“SVG 优先、高分 PNG 补充、根目录 ICO 兜底、移动端独立规范”** 四层结构，即可同时兼顾桌面高分屏、深浅色主题和 iOS/Android 主屏幕。搜索引擎方面要注意：Google 不支持 SVG，搜索结果里的图标来自 ICO / PNG，且需要首页显式声明。

---

## 一、标准 `<head>` 与清单配置模板

将以下声明放入首页及全站页面模板的 `<head>` 中（若将图标统一存放在 `/favicon/` 子目录，同步调整下方 `href` 路径即可，但**网站根目录仍应保留 `/favicon.ico`**）：

```html
<!-- 1. 现代浏览器首选：SVG 矢量图标（无限缩放，支持深浅模式自适应） -->
<link rel="icon" href="/favicon.svg" type="image/svg+xml">

<!-- 2. 高分位图补充：兼容 Safari 18 及更早版本等不支持 SVG 的浏览器；Google 搜索不支持 SVG，会从 ICO / PNG 中取图 -->
<link rel="icon" href="/favicon-96x96.png" type="image/png" sizes="96x96">

<!-- 3. 经典兜底：兼容老旧浏览器（显式声明 sizes="32x32"，避免 Chrome 误选 ICO 或同时下载 ICO 与 SVG） -->
<link rel="icon" href="/favicon.ico" sizes="32x32">

<!-- 4. 苹果 iOS / iPadOS 添加到主屏幕图标（180×180 实底正方形 PNG） -->
<link rel="apple-touch-icon" href="/apple-touch-icon.png" sizes="180x180">

<!-- 5. Android 与 PWA 应用清单（声明 192×192 与 512×512 PNG） -->
<link rel="manifest" href="/site.webmanifest">
```

配套的 `/site.webmanifest`（JSON 格式）：

```json
{
  "name": "站点名称",
  "short_name": "简称",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ],
  "theme_color": "#ffffff",
  "background_color": "#ffffff",
  "display": "standalone"
}
```

## 二、核心格式职责与避坑要点

### 1. 现代浏览器首选：SVG 引用（`favicon.svg`）

在 `<link>` 中声明 `type="image/svg+xml"` 是现代网页图标的首选方案：

- **无限无损缩放**：矢量图形在 1080P、Retina、4K 等任意 DPI 屏幕和缩放比例下均保持边缘锐利，且文件体积通常远小于多张高清位图。
- **支持深浅色主题自适应**：可在 SVG 源码内部嵌入 `<style>` 与 `@media (prefers-color-scheme: dark)`，让图标随浏览器深色/浅色标签栏自动切换配色，避免黑色轮廓 Logo 在暗黑标签页中“隐身”。

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 64 64">
  <style>
    path { fill: #18181b; }
    @media (prefers-color-scheme: dark) {
      path { fill: #f4f4f5; }
    }
  </style>
  <path d="M12 12h40v40H12z" />
</svg>
```

- **服务器必须以 `image/svg+xml` 返回**：MIME 类型不对时，浏览器不会把它当图标显示（GitHub Pages 默认已正确返回）。
- **兼容性边界**（据 Can I use）：Chrome 80+、Edge 80+、Firefox 41+、Safari / iOS Safari 26+ 支持 SVG Favicon；**Safari 18.7 及更早版本**不支持。
- **搜索引擎不使用 SVG**：Google 搜索结果图标仅支持 BMP、GIF、ICO、PNG、JPEG、PPM、TIFF，不包含 SVG。SVG 只服务于浏览器标签页，搜索结果里的图标来自 ICO / PNG，因此后两者必须保留。

---

### 2. 经典兜底与 Chromium 优先级避坑：`favicon.ico`

`.ico` 是封装了多个固定尺寸位图（推荐在文件内同时打包 `16×16`、`32×32`、`48×48`）的容器格式，主要服务于不支持 SVG 的旧版浏览器与特定系统环境。

- **为什么必须写 `sizes="32x32"`**：同时声明 `.svg` 和 `.ico` 时，Chrome 对 `.ico` 的 `sizes` 写法有两个已知问题（据 Evil Martians《How to Favicon》更新记录）：
  - **不写 `sizes`**：Chrome 会选 ICO，不用 SVG。
  - **写成 `sizes="any"`**：能让 Chrome 选 SVG，但会把 ICO 和 SVG **同时下载**。
- **正确写法**：给 `.ico` 标注 `sizes="32x32"`，`favicon.svg` 保持常规 `type="image/svg+xml"` 声明。这样 Chrome 选 SVG 且不重复下载，老旧客户端回退到 `.ico`。

---

### 3. 根目录 `/favicon.ico` 与搜索引擎自动检索

很多项目会把图标资源整理进 `/favicon/` 或 `/assets/` 子目录中，但**依然强烈建议在网站根目录放置一份 `/favicon.ico`**（即 `https://你的域名/favicon.ico`）：

1. **非 HTML 资源与简易客户端的隐式兜底**：直接打开站内 PDF、图片直链，或 RSS 阅读器之类的工具，没有 `<head>` 可读，会直接向根目录 `/favicon.ico` 发请求（Evil Martians 也据此建议保留根目录 ICO）。
2. **搜索引擎的读取方式**：
   - **Google（官方文档明确）**：只读取**站点首页 `<head>`** 中的 `<link>`。支持的 `rel` 值有 `icon`、`shortcut icon`（历史写法）、`apple-touch-icon`、`apple-touch-icon-precomposed`。官方文档**没有写**“找不到时回退 `/favicon.ico`”，所以首页必须显式声明。
   - **Bing、百度等**：本文未找到官方文档说明其回退规则。根目录 `/favicon.ico` 作为通用约定保留，但不要把它当作“不写 `<link>` 也能被收录”的保证。

**Google 搜索结果图标的官方条件：**

- **格式**：BMP、GIF、ICO、PNG、JPEG、PPM、TIFF。**不含 SVG**。
- **尺寸与比例**：必须是 **1:1 正方形**，最小 `8×8px`；官方**推荐大于 `48×48px`**，让图标在各种展示面上都清晰。`16×16` 虽达到下限，但清晰度差，所以建议保留 `96×96` PNG。
- **站点范围**：每个**主机名**只支持一个图标，且只认域名或子域名的首页，子目录首页（如 `example.com/news`）不支持。本文涉及的三个站点各自是独立子域名，各自首页单独声明即可。
- **允许爬虫访问**：`Googlebot` 必须能抓取首页（含重定向），`Googlebot-Image` 必须能抓取图标文件，两者都不能被 `robots.txt` 屏蔽。
- **URL 稳定**：不要频繁改图标 URL。图标更新后，Google 重新抓取可能要几天到几周。
- **不保证展示**：满足全部条件也只是“有资格”，是否展示由 Google 决定。

---

### 4. 苹果、安卓与媒体封面生态（PNG 的职责）

在现代方案中，PNG 除了作为不支持 SVG 时的桌面端高清补充（如 `96×96`）外，主要承担移动端与 PWA 场景：

- **iOS / iPadOS 主屏幕（`apple-touch-icon`）**：
  - 准备 **`180×180` 像素**的 PNG。
  - **禁止透明背景**：iOS 系统不支持桌面 Web Clip 透明通道，会自动将透明区域强行填充为纯黑。请提供带有完整纯色/品牌背景的正方形图片。
  - **禁止预切圆角**：直接提供直角正方形图片，iOS 会自动套用系统标准圆角遮罩。
- **Android 与 PWA（`site.webmanifest`）**：
  - 在清单中至少提供 **`192×192`**（桌面快捷方式）与 **`512×512`**（安装与启动闪屏）两张 PNG。
  - 可选：再加一张 `purpose: "maskable"` 的 512×512 图标（主体留在中央安全区内），避免 Android 圆形遮罩裁掉 Logo 边缘。
- **Media Session 媒体封面（如 iOS 灵动岛）**：
  - 若网站包含音视频播放器，可通过 **Media Session API**（`navigator.mediaSession.metadata` 的 `artwork` 字段）指定锁屏、控制中心与灵动岛里的封面，**显式指定后以 `artwork` 为准**。
  - 未指定时，系统可能回退到页面图标（站长在 iOS 上实测会显示 `apple-touch-icon`，但本文未找到官方文档确认）。
  - 透明背景在这些系统媒体界面里同样可能被压成黑色，封面建议使用实底图片（JPG 或无透明通道的 PNG）。

## 三、极简全端图标清单

| 文件路径 | 格式与尺寸 | 核心用途 |
|---|---|---|
| `/favicon.ico` | ICO（含 `16/32/48`） | 网站根目录默认检索、旧版浏览器及非 HTML 资源兜底 |
| `/favicon.svg` | SVG（矢量） | 现代浏览器标签页首选，支持无限缩放与深浅色自适应 |
| `/favicon-96x96.png` | PNG（`96×96`） | 不支持 SVG 时的桌面清晰位图补充，也是 Google 搜索结果可用的高清图（Google 不支持 SVG） |
| `/apple-touch-icon.png` | PNG（`180×180` 实底） | iPhone / iPad Safari“添加到主屏幕”与起始页书签图标 |
| `/icon-192.png` / `/icon-512.png` | PNG（`192×192`、`512×512`） | `site.webmanifest` 中用于 Android 桌面与 PWA 安装 |
