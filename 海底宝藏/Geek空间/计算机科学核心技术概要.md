## 一、计算机硬件体系与网络底层

### 1.1 冯·诺依曼计算机五大核心部件
现代通用计算机统一遵循**冯·诺依曼体系结构**，由五大基础部件协同工作：

```
       ┌───────────────────────────────┐
       │         中央处理器 (CPU)       │
       │  ┌───────────┐ ┌───────────┐  │
       │  │ 控制器 CU │ │ 运算器 ALU│  │
       │  └─────┬─────┘ └─────┬─────┘  │
       │        │   ┌─────────┴───────┐│
       │        └───┤ 寄存器组 / Cache││
       │            └─────────────────┘│
       └───────────────▲───────────────┘
                       │ 总线连接
   ┌───────────┐       │       ┌───────────┐
   │ 输入设备  ├───────┼──────►│ 输出设备  │
   │ (键盘/鼠标)│       │       │(显示器/打印)
   └───────────┘       ▼       └───────────┘
               ┌───────────────┐
               │    存储器     │
               │ 主存RAM/辅存Disk│
               └───────────────┘
```

1. **运算器（ALU, Arithmetic and Logic Unit）**：执行算术运算（加减乘除）与逻辑运算（与、或、非、异或）。
2. **控制器（CU, Control Unit）**：计算机的“神经中枢”，负责指令的抓取、译码，并向各个部件发送控制电信号协调节拍。
   > **核心公式**：$$\text{CPU（中央处理器）} = \text{控制器 (CU)} + \text{运算器 (ALU)} + \text{寄存器组 (Registers)} + \text{片上缓存 (Cache)}$$
3. **存储器（Memory）**：
   - **主存（内存 RAM）**：CPU 可直接高频寻址，读写极快，断电后数据丢失。
   - **辅存（外存 Disk/SSD）**：容量大、单位成本低，用于持久化保存数据，断电不丢失。
4. **输入设备（Input Device）**：将现实中的物理信息（键盘击键、鼠标位移）转化为二进制电信号。
5. **输出设备（Output Device）**：将计算机处理完毕的二进制信息转化为人类可感知的形式（图像、打印字符等）。

### 1.2 CPU 指令周期（Instruction Cycle）四阶段
CPU 执行任何程序，在底层均转化为一条条机器指令的循环执行四步法：

| 阶段 | 动作名称 | 英文术语 | 具体执行内容 |
| :---: | :--- | :--- | :--- |
| **1** | **取指令** | **Fetch** | 根据程序计数器（PC）指定的内存地址，将下一条待执行指令从内存读取到指令寄存器（IR）。 |
| **2** | **指令译码** | **Decode** | 控制器分析该指令的操作码，判定要执行的操作类型（加法、跳转等），并准备所需操作数。 |
| **3** | **执行指令** | **Execute** | 控制器驱动运算器（ALU）或其他部件，完成具体的计算或硬件控制动作。 |
| **4** | **访存/写回** | **Store / Writeback** | 将计算结果存入通用寄存器，或按指令要求写回主存指定地址单元。 |

### 1.3 底层数据表示机制（二进制、补码与浮点数）
- **二进制底座**：底层硅基电路仅有导通与截止两种物理状态，对应数字 `0` 与 `1`。
- **原码、反码与补码**：
  - 计算机内部**统一采用补码表示有符号整数**。
  - **核心价值**：
    1. **简化硬件电路**：将数学上的减法运算转换为加法运算（$A - B = A + (-B)_{\text{补}}$），CPU 内部仅需设计加法器即可完成减法运算；
    2. **消除零的二义性**：原码存在 $+0$（`00000000`）和 $-0$（`10000000`），补码的 $0$ 拥有唯一编码（`00000000`）；
    3. **多利用一个负数**：8 位补码可表达 $-128 \sim +127$（原码仅为 $-127 \sim +127$）。
- **浮点数（IEEE 754 标准）**：
  采用科学计数法表示实数，通过将 32 位（单精度 float）或 64 位（双精度 double）划分为 **符号位（Sign）**、**指数阶码（Exponent）** 和 **有效尾数（Mantissa）**，以有限位数覆盖极其宽广的数值范围。

### 1.4 存储器金字塔层次体系
为平衡“访问延迟”与“制造成本”，现代计算机构建了金字塔式存储层级：

```
       ▲
      / \        [寄存器 Registers]     延迟 < 1 ns     容量：几十字节~几KB
     /   \       -----------------------------------------------------
    / Cache\     [高速缓存 L1/L2/L3]     延迟 1~10 ns    容量：几十KB~几十MB
   /---------\   -----------------------------------------------------
  /   主存    \   [系统内存 RAM]         延迟 50~100 ns  容量：8GB~128GB
 /-------------\ -----------------------------------------------------
/   外部辅存    \ [固态硬盘 SSD / HDD]   延迟 微秒~毫秒级 容量：512GB~数十TB
=================
```

- **程序局部性原理**：
  - **时间局部性**：刚被访问过的数据很可能短期内再次被访问（如循环体内变量）；
  - **空间局部性**：某个存储单元被访问，其相邻的连续地址单元很可能即将被访问（如数组遍历）；
  - **Cache 的核心作用**：利用局部性原理，提前将内存块载入 CPU 内部高速缓存，大幅削减 CPU 等待内存读取的空转周期。

### 1.5 系统总线三通道（DB / AB / CB）
总线是主板上各个芯片间共享的数据传输公路：
- **数据总线（DB, Data Bus）**：**双向**总线，用于传输实际的数据内容。总线宽度（如 32 位、64 位）决定了一次并行传输的数据吞吐能力。
- **地址总线（AB, Address Bus）**：**单向**总线，由 CPU 发出，指定数据要写入或读出的物理存储单元地址。总线宽度决定了最大寻址上限（如 32 位对应 $2^{32} = 4\text{GB}$）。
- **控制总线（CB, Control Bus）**：传输微操作控制信号与硬件状态反馈（如：读信号、写信号、中断请求、时钟同步）。

### 1.6 网络拓扑结构与核心设备连通逻辑

```
  [互联网云端]
       │ (光纤 Fiber Optic)
       ▼
 [光猫 Modem] ────────── 牵网入户：将光纤光信号调制解调为网线电信号
       │ (网线连接 WAN 口)
       ▼
[路由器 Router] ──────── 核心管家：NAT 转换、DHCP 动态内网 IP 分配、路由寻址
   ├── 无线 Wi-Fi 覆盖 ─► 手机 / 平板 / 笔记本
   ├── 千兆直连网线 ───► 台式电脑 PC
   └── 网线扩展口 ─────► [交换机 Switch] ── 端口扩充：纯物理扩展网口，不分配 IP
                               ├──► 智能电视 (Smart TV)
                               └──► 私有云存储 (NAS)
```

- **公网 IP（Public IP）**：全球互联网公网路由的唯一身份证（如宽带运营商分配的对外出口 IP 地址）。
- **私网 IP（Private IP）**：局域网内部流通的门牌号（如 `192.168.1.x`），仅在路由器后方有效，不可在公网路由。

## 二、Java 软件工程与编程规范

### 2.1 架构哲学：坚持“一类一文件”的核心工程价值
在实际生产中，坚决反对将所有功能代码塞进单个 `.java` 文件，必须严格贯彻**“一类一文件”（One Class Per File）**规范：
1. **检索效率（查字典效应）**：文件名与类名严格一致，排查问题时通过文件树或快捷键秒级定位；
2. **变更隔离（降低耦合并发）**：单个类的语法错误或重构不会污染其他业务模块，避免“牵一发而动全身”；
3. **版本管理（Git 协同）**：细粒度文件拆分使得多人协作时修改不同文件，极大规避代码合并冲突（Merge Conflict）。

---

### 2.2 JDK 根目录规范与核心构件职能
标准 JDK 安装目录下的文件夹分工如下：

```plaintext
jdk-xx/
├── bin/          <-- 核心工具集：java.exe (启动 JVM)、javac.exe (编译为 class)、javadoc.exe、jdb.exe
├── conf/         <-- 配置文件：包含安全策略 (security)、网络及 JVM 核心运行参数配置
├── include/      <-- C/C++ 语言头文件：提供 JNI (Java Native Interface) 跨语言调用所需的本地接口定义
├── jmods/        <-- Java 原生模块包：JDK 9+ 模块化系统的基础库分发形式
├── lib/          <-- 类库与原材料：存放 Java 运行时底层核心类库
└── release       <-- JDK 基础属性文件：声明当前 Java 的详细版本号与架构信息
```

### 2.3 包声明（Package）与物理磁盘路径的映射规则
Java 语言规定，源码中的逻辑包声明必须与操作系统的物理文件夹目录**绝对对齐**：

```
操作系统磁盘物理路径：
D:/Project/src/main/java/com/shaoxia/handler/UserHandler.java
```

在 `UserHandler.java` 文件首行，必须严格声明相符的包路径：
```java
package com.shaoxia.handler; // 必须与目录路径 com/shaoxia/handler 严格一致

import java.util.List;

public class UserHandler {
    // 业务代码
}
```

### 2.4 代码风格流派：K&R 行末派 vs Allman 换行派

| 维度 | 流派一：行末派（K&R 风格） | 流派二：换行派（Allman 风格） |
| :--- | :--- | :--- |
| **代码形态** | ```java<br/>public void swordPlay() {<br/>    if (isReady) {<br/>        System.out.println("拔剑！");<br/>    }<br/>}<br/>``` | ```java<br/>public void swordPlay()<br/>{<br/>    if (isReady)<br/>    {<br/>        System.out.println("拔剑！");<br/>    }<br/>}<br/>``` |
| **核心优点** | 节省垂直空间，屏幕承载行数多，视觉紧凑连贯。 | 大括号独立换行成对对齐，层级块视觉清晰。 |
| **适用领域** | **Java 官方规范、Google Java Style、Spring 框架绝对推荐主流**。 | C#、C++、Windows 平台原生开发常见。 |

### 2.5 方法设计本质：`void` 与 `return` 的流水线数据流
将函数调用比作“厂长（调用方）与工人（被调用方法）”的协作：

```java
// 错误模式：工人 A 使用 void，成果留在工人内部，方法结束后栈帧销毁，产物直接丢弃
public static void makeStickWrong(String wood) {
    String stick = wood + "削成的木棍";
}

// 正确模式：工人 A 明确返回类型 String，通过 return 把成果移交给调用方
public static String makeStickRight(String wood) {
    return wood + "削成的木棍"; // 成品交回
}

public static void paintRed(String stick) {
    System.out.println(stick + "变成了红色");
}

public static void main(String[] args) {
    // 厂长稳稳接收成品并赋值给变量
    String myStick = makeStickRight("红松木");
    
    // 厂长再将此变量作为输入参数交接给下一个环节处理
    paintRed(myStick);
}
```

### 4.2 登录业务端到端六步流转全景

#### 第一步：江湖来信（客户端发出请求）
前端向 `POST /api/login` 提交 JSON 载荷：
```json
{
  "username": "张三",
  "password": "123"
}
```

#### 第二步：掌柜迎客（UserController 路由与参数接入）
DispatcherServlet 将请求分发至对应 Controller 方法，使用 `@RequestBody` 解析请求体：
```java
@RestController
@RequestMapping("/api")
public class UserController {

    @Autowired
    private UserService userService;

    @PostMapping("/login")
    public ResponseEntity<?> login(@RequestBody LoginDTO dto) {
        try {
            // 调用业务层
            User user = userService.login(dto.getUsername(), dto.getPassword());
            return ResponseEntity.ok(Result.success("登录成功", user));
        } catch (Exception e) {
            return ResponseEntity.badRequest().body(Result.error(400, e.getMessage()));
        }
    }
}
```

#### 第三步：账房核对（UserServiceImpl 业务处理中枢）
标有 `@Service` 的实现类已被 Spring IoC 容器纳管，并注入了 Mapper 代理对象：
```java
@Service
public class UserServiceImpl implements UserService {

    @Autowired
    private UserMapper userMapper;

    @Override
    public User login(String username, String password) {
        // 委托持久层查询
        User user = userMapper.findByUsername(username);
        
        // 业务规则校验与脱敏（详见第五步）
        ...
    }
}
```

#### 第四步：探查生死簿（UserMapper 动态代理执行 SQL）
MyBatis 在框架启动时为 `@Mapper` 接口生成动态代理对象，将方法映射到对应的 SQL 语句：
```java
@Mapper
public interface UserMapper {
    @Select("SELECT * FROM sys_user WHERE username = #{username}")
    User findByUsername(@Param("username") String username);
}
```
底层执行 `SELECT * FROM sys_user WHERE username = '张三'`，并将数据库返回的一行记录反射填充到 `User` 实体中。

#### 第五步：门派规矩校验（Service 核心逻辑与脱敏）
```java
// 1. 查无此人：用户不存在
if (user == null) {
    throw new BusinessException("该用户名不存在！");
}

// 2. 暗号不对：密码比对（生产推荐 passwordEncoder.matches 散列校验）
if (!user.getPassword().equals(password)) {
    throw new BusinessException("密码错误！");
}

// 3. 安全脱敏：将敏感字段置空，防止通过网络泄露
user.setPassword(null);
return user;
```

#### 第六步：飞鸽传书（Controller 响应客户端）
- **正常完成**：封装 HTTP 200 与脱敏后的数据对象，由 Jackson 序列化为 JSON 交付前端；
- **校验失败**：全局异常处理器或 catch 块捕获业务异常，封装 HTTP 400 与错误消息交付前端。

### 5.2 工业级 `start.bat` 启动脚本标准规范
针对生产中管理员权限运行工作目录偏移、带空格路径启动报错、中文乱码三大坑点，标准加固脚本如下：

```bat
@echo off
:: ========================================================
:: 1. 动态锚定真实目录（杜绝以管理员身份运行时工作目录漂移到 system32）
:: ========================================================
set "BASE_DIR=%~dp0"
cd /d "%BASE_DIR%"

:: ========================================================
:: 2. 解耦系统环境：使用程序包自带的便携版 JRE
::    使用 javaw.exe 代替 java.exe，静默后台启动，不留黑色控制台窗口
:: ========================================================
set "MY_JAVA=.\jre\bin\javaw.exe"

:: ========================================================
:: 3. 规避 Windows start 命令经典 Bug，并强制统一 UTF-8 编码
::    start "" 中的空双引号是窗口标题占位符，防止首个带空格路径被误认为是窗口名
::    -Dfile.encoding=utf-8 彻底杜绝读取文件和数据库时的中文乱码
:: ========================================================
start "" "%MY_JAVA%" -Dfile.encoding=utf-8 -jar "app.jar"

exit
```

### 5.3 WinRAR 自解压（SFX）无残留绿色化配置
无需用户安装 Java 环境，打包为单文件 `App.exe` 的关键配置步骤：
1. **工作区归集**：将 `app.jar`、`jre/`（精简 JRE 文件夹）、`start.bat`、`icon.ico` 置于同一文件夹；
2. **创建压缩文件**：全选文件 $\rightarrow$ 右键选择“添加到压缩文件...” $\rightarrow$ 格式选 **RAR** $\rightarrow$ 勾选 **“创建自解压格式压缩文件”**；
3. **高级 SFX 选项配置**：
   - **常规 $\rightarrow$ 解压路径**：填入 `%TEMP%\MyAppTool`（使用系统临时目录，不留垃圾）；
   - **设置 $\rightarrow$ 解压后运行**：填入 `start.bat`；
   - **模式**：勾选 **“解包到临时文件夹”**，安静模式选择 **“全部隐藏”**（无界面后台静默解压）；
   - **更新 $\rightarrow$ 覆盖方式**：选择 **“覆盖所有文件”**；
   - **文本和图标**：点击“从文件加载自解压图标”，选取准备好的 `icon.ico`。
4. **交付成果**：生成的 `.exe` 双击即可运行，后台自动释放环境并在关闭后由系统回收，实现真正的“伪绿色版”交付。
