# 💯在电脑上建立一个测试后端

最近在搞前端组件，我想把原生繁琐的 `fetch`（`GET` 和 `POST` 标准请求）封装成一个开箱即用的“黑盒”工具函数，让调用语句尽可能简单一点。

然后呢，我发现手头并没有一个现成的后端用来测试。为了实现一次完美的闭环测试，我决定在本地新建一个极简的后端测试接口——顺便，这里又可以水一篇硬核实用的小教学了。

## 1. 准备工作：确认环境与创建项目

在动手之前，请先确认你的电脑上已经安装了 **Node.js**（可以在终端输入 `node -v` 检查，能看到版本号即可）。

确认无误后，直接回到你的电脑桌面，新建一个文件夹，命名为 `tukuai-server`。这就是我们后端服务器的大本营。

## 2. 扫清障碍：解除终端权限拦截

在 Windows 系统下，PowerShell 默认的安全机制（执行策略）很可能会拦截 `npm` 脚本运行。为了不让它拦路，我们需要先执行一行“一劳永逸”的命令。

打开刚才新建的 `tukuai-server` 文件夹，**按住键盘上的 `Shift` 键，在文件夹空白处点击鼠标右键**，选择“在此处打开 PowerShell 窗口”或“在终端中打开”，然后输入并回车运行以下命令（如果终端弹出是否更改执行策略的询问，输入 `Y` 并回车即可）：

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

## 3. 核心步骤：安装框架与依赖

一个现代化的极简后端，离不开两大神器：

* **`express`**：最经典、最轻量的 Node.js 后端框架。
* **`cors`**：跨域神器。如果没有它，你的前端 HTML 请求后端时会被浏览器同源策略无情拦截；它也是很多新手最容易漏装、导致启动时报 `Cannot find module 'cors'` 错误的头号元凶。

在终端中依次运行以下两行命令，初始化项目并把这两个依赖装好：

```powershell
npm init -y
npm install express cors
```

## 4. 注入灵魂：编写服务端代码

在 `tukuai-server` 文件夹里新建一个文本文件，重命名为 `server.js`。

> **⚠️ 新手防坑提醒**：Windows 默认隐藏了已知文件类型的扩展名！改名时请务必在文件夹顶部菜单勾选**“显示 -> 文件扩展名”**，确保它叫 `server.js` 而不是偷偷变成了 `server.js.txt`（否则后面运行会报找不到模块的错误）。

用任意代码编辑器（或记事本）打开 `server.js`，复制并粘贴下面这段极简代码：

```javascript
// ==========================================
// TuKuai 微型后端 (server.js)
// ==========================================
const express = require('express');
const cors = require('cors');
const app = express();

// 让后端允许跨域，并自动解析前端发来的 JSON (这就相当于后端拆包裹的黑盒)
app.use(cors());
app.use(express.json());

// 模拟一个数据库 (存放在内存里的数组)
let tukuaiDatabase = [
    { id: 1, title: "系统留言", body: "少侠，欢迎连接到你自己的后端服务器！" }
];

// 【接口 1：响应 GET 请求】前端来要数据
app.get('/api/posts', (req, res) => {
    console.log("🚚 收到前端的 GET 请求，正在下发数据...");
    res.json(tukuaiDatabase); // 把整个数据库打包发给前端
});

// 【接口 2：响应 POST 请求】前端来交数据
app.post('/api/posts', (req, res) => {
    console.log("🚚 收到前端发来的 POST 包裹：", req.body);
    
    // 把前端发来的数据加上一个新 ID，存进我们的“数据库”
    const newPost = {
        id: tukuaiDatabase.length + 1,
        title: req.body.title,
        body: req.body.body
    };
    tukuaiDatabase.push(newPost); // 真实保存！
    
    // 给前端发回执，告诉它状态是 201 (创建成功)
    res.status(201).json({ success: true, message: "后端已入库！", data: newPost });
});

// 启动服务器
app.listen(3000, () => {
    console.log("🚀 TuKuai 后端已启动！监听端口 3000...");
    console.log("测试地址: http://localhost:3000/api/posts");
});
```

## 5. 点火发射：运行你的服务器

回到刚才的终端窗口，输入启动命令：

```powershell
node server.js
```

## 6. 见证奇迹：亲手打通 GET 与 POST

如果一切顺利，你的终端里会打印出这样的画面：

```powershell
PS C:\Users\TuKuai\Desktop\tukuai-server> node server.js
🚀 TuKuai 后端已启动！监听端口 3000...
测试地址: http://localhost:3000/api/posts
```

现在我们来做一次完整的收发验货：

1. **测试 `GET`（拿数据）**：直接用浏览器打开 `http://localhost:3000/api/posts`，你会看到页面上显示出了那条“少侠，欢迎连接到你自己的后端服务器！”的 JSON 数据，同时黑窗口里会跳出 `🚚 收到前端的 GET 请求`。
2. **测试 `POST`（交数据）**：在刚才的浏览器页面按下 `F12` 打开开发者工具，切换到 **Console（控制台）**，粘贴下面这段原生 `fetch` 代码并回车：

```javascript
fetch('http://localhost:3000/api/posts', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ title: "测试包裹", body: "原生 fetch 写起来也太啰嗦了吧！" })
}).then(r => r.json()).then(console.log);
```

回车瞬间，你会看到终端黑窗口立马打印出 `🚚 收到前端发来的 POST 包裹`！此时再去刷新一下浏览器页面，原本只有 1 条的数据库已经变成 **2 条**了！

## 7. 底层冷知识与下集预告

**💡 为什么关掉黑窗口，刚才存的数据就没了？**

因为 `tukuaiDatabase` 这个数组变量只存在于运行这段代码的 Node.js 进程的**系统内存（RAM）**里，并没有写入硬盘。它面临着一个残酷的物理现实：**一旦你把黑底白字的 PowerShell 终端关掉，或者在终端里按了 `Ctrl+C` 停止服务器进程，这块内存就会被操作系统立刻回收清空，下次重启又会回到初始的那 1 条数据。**
